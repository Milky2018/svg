## Description
SVG `<filter>` elements and filter primitives are not parsed into a render-time graph. The existing `Filter` enum is a programmatic, linear image-effect list and cannot represent named intermediate results, multiple inputs, filter regions, or graph primitives such as `feBlend`, `feComposite`, and `feMerge`.

## Design
Add a document filter registry and an internal graph representation with named inputs and results. Evaluate graph nodes against isolated SourceGraphic/SourceAlpha buffers, honor the filter region, and feed the final result into the shared mask/opacity/blend compositing pipeline. Do not mislabel the existing sequential programmatic filters as SVG graph support.

## Acceptance Criteria
- [x] Parsed `filter="url(#...)"` resolves a document filter definition.
- [x] Linear primitives can consume SourceGraphic and named prior results.
- [x] Multi-input blend/composite behavior has pixel-level tests.
- [x] Container filter output is masked, opacified, and blended in browser order.
- [x] Filter-region clipping and transparent out-of-bounds sampling are tested.
- [x] All-target strict checks and tests pass.

## Close Notes

Added a document filter registry, named SourceGraphic/SourceAlpha graph inputs and results, filter-region clipping, and evaluators for feColorMatrix, feGaussianBlur, feOffset, feBlend, and Porter-Duff/arithmetic feComposite. The shared isolated pipeline now applies filter output before mask and opacity, then performs the node blend. Verified with `moon info`, `moon check --target all --deny-warn`, `moon test --target all` (305 tests on wasm, wasm-gc, JavaScript, and native), and `git diff --check`. Remaining SVG Filter Effects primitive coverage is tracked in ISS-016.
