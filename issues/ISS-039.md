## Description
Replace the divergent root and SVG-module README files with a deliberate documentation hierarchy. The current Japanese `README.md` advertises game utilities while the English `README.mbt.md` documents the newer rendering facade, and `modules/svg` repeats the same split while publishing `README.md`.

## Design
Choose one canonical source per documentation role. The repository README should explain the two-member workspace and direct users to published module documentation. The SVG module should prefer a checked `README.mbt.md` with `README.md` synchronized or linked where supported. Examples should exercise current public APIs rather than remain unchecked pseudocode. Document the accepted SVG and CSS boundaries without promising browser pixel identity or dynamic browser behavior.

## Acceptance Criteria
- [x] Root and module README roles are explicit and contain no contradictory feature claims.
- [x] `modules/svg/moon.mod` publishes the canonical SVG README.
- [x] Core install, parse, render, structured diagnostics, and image-resolver examples are checked where practical.
- [x] Removed or relocated APIs are no longer advertised.
- [x] CSS ownership, supported static semantics, and intentional exclusions match ISS-043 and ISS-044.
