# ISS-024: Add host-provided raster image resolution

## Description
`<image>` currently retains only embedded SVG data and silently discards PNG, JPEG, filesystem, and network references. The core renderer should accept decoded RGBA images from its host without embedding codecs, filesystem access, or network access in the SVG package.

## Design
Preserve the authored `href` and expose a synchronous callback on `RenderContext`. The host resolves and decodes references into `Image`; the SVG renderer owns viewport mapping, `preserveAspectRatio`, full affine sampling, clipping, and alpha compositing. Keep embedded SVG data support inside the core for compatibility.

## Acceptance Criteria
- [x] Parsing preserves the exact `href` or `xlink:href` value.
- [x] A public image resolver callback receives unresolved references and may return decoded RGBA `Image` data.
- [x] Unresolved references render nothing and do not fail the document render.
- [x] Raster images honor default meet, `none`, and slice viewport mapping.
- [x] Raster images honor rotation and skew rather than using an axis-aligned blit.
- [x] Raster alpha is composited through the normal pixel setter.
- [x] Embedded SVG data images remain supported without invoking the host resolver.
- [x] High-level document, scene, node, and string rendering APIs accept a resolver.
- [x] All-target strict checks and tests pass.
