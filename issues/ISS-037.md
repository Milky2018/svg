# ISS-037: Define the supported SVG public surface

## Description
Decide which APIs belong in a focused SVG parser, scene model, and deterministic renderer before removing inherited utilities. The current module also exposes camera navigation, tween animation, pointer events, collision helpers, object pooling, particles, path following, sprites, image editing helpers, and other game-oriented facilities.

## Design
Review the generated SVG interface by responsibility and produce an explicit keep, remove, relocate, or internalize decision for every questionable public family. Local usage counts are evidence only and must not be treated as proof that external consumers do not exist. Preserve parsing, SVG resource modeling, geometry required by the renderer, the rendering facade, typed diagnostics, and host image resolution unless separately decided otherwise.

## Decisions
- The module is a focused SVG document parser and renderer, not a game-scene toolkit.
- `SVGDocument` and the `SVGNode` tree remain the document model. The dynamic `Scene` abstraction and its dirty tracking, z-order mutation, and scene-rendering entry points will be removed.
- Camera navigation, hit testing, custom tween animation, pointer events, collision helpers, generic object pooling, particles, path following, sprites, animated sprites, and general bitmap-toolkit operations will be removed rather than moved into another module.
- SVG resource models, rendering diagnostics, host image resolution, and the minimal `Image`/`Color` facilities required to supply and consume raster pixels remain.
- Renderer algorithms such as path flattening, gradient lookup tables, pixel blending, filter kernels, and matrix helpers should become private unless a later interface decision explicitly retains them.
- The canonical rendering interface will be `render_svg(source, width, height, options) -> RenderResult` and `render_svg_document(document, width, height, options) -> RenderResult`, plus the simple `render_svg_to_image` convenience and expert `render_path_commands_to_image` entry points.
- Remove `parse_svg`, all `*_with_resolver` combinations, node and scene rendering entry points, and the old document-to-image variants. Image resolution and future rendering controls go through `RenderOptions`; diagnostics and output go through `RenderResult`.
- Preserve manual document construction for external DOM adapters, generated graphics, and tests. `SVGDocument`, `SVGNode`, and authored SVG domain/resource types remain public.
- Hide parser and renderer bookkeeping such as `*_is_set`, dirty state, previous bounds, reference-resolution masks, and raw registry maps. Remove public `*Registry` types and expose deliberate `SVGDocument` resource-registration methods instead.
- Retain domain operations that hide real SVG complexity: `SVGNode::new(Shape)`, `parse_path`, `parse_transform`, `path_bbox`, color constructors, and constructors for authored SVG resources.
- Remove shallow free node constructors and non-standard resource shortcuts such as `rect`, `circle`, `line`, `path`, `text`, `group`, `LinearGradient::horizontal/vertical`, and `Marker::arrow/dot`.
- Internalize renderer mechanics including degree/radian and identity-matrix helpers, path-to-polyline conversion, gradient lookup tables and direct samplers, clip/pattern point queries, and marker transform calculation.
- Reduce `Image` to the raster interchange type required by rendering and host image resolution: validated construction from dimensions and pixels, dimensions and read-only pixel access, safe pixel reads/writes, and basic filled-image construction. Keep `Color` and `ImageSampling` as authored/rendering domain values.
- Remove public bitmap editing, in-place effects, filter application, mask application, blending, blitting, flips, rotations, sub-images, unchecked writes, drawing helpers, cloning, and color-matrix/luminance helpers. Renderer implementations may retain private equivalents.
- Retain only the basic SVG `Shape::Text` document representation, XML text parsing, computed paint and `font-size`, and the current minimal renderer fallback. Remove the disconnected `TextBlock`, `TextSpan`, `TextStyle`, wrapping, overflow, whitespace, writing-mode, orientation, decoration, weight, anchor, and baseline toolkit. A future `<text>/<tspan>` layout model must be designed from SVG semantics instead of preserving this approximation.
- Ship the cleanup as the breaking `0.4.0` interface. Remove rejected APIs directly without deprecated aliases or compatibility layers, and provide a concise migration table for the retained render/document paths. Scene, game utilities, bitmap editing, and general text layout intentionally have no replacement interface.

## Acceptance Criteria
- [x] A public-surface inventory groups the current API by responsibility.
- [x] Camera, hit testing, animation, events, collision, pooling, particles, path following, sprites, standalone image effects, scene mutation, and convenience constructors each have an explicit disposition.
- [x] Compatibility and versioning consequences are recorded before implementation begins.
- [x] The accepted boundary distinguishes SVG semantics from general game-engine utilities.

## Notes
- 2026-07-22: This is the first cleanup discussion item; it makes no source changes by itself.
- 2026-07-22: Discussion started. The initial proposal is to keep the SVG document/rendering model deep and remove or relocate general game-engine and bitmap-toolkit facilities from its public interface.
- 2026-07-22: Accepted the focused document-renderer direction. Out-of-scope game and bitmap utilities will be deleted, not moved, and `Scene` will not remain as a second dynamic document model.
- 2026-07-22: Accepted two structured rendering entry points for source strings and `SVGDocument`, one simple image convenience, and one expert direct-path entry point. Combinatorial resolver, node, scene, and document-image variants will be removed.
- 2026-07-22: Accepted external construction of SVG documents as a supported seam while hiding registries and computed/rendering state behind the document interface.
- 2026-07-22: Accepted removing shallow convenience constructors and making sampling, flattening, point-query, lookup-table, and marker-transform mechanics private.
- 2026-07-22: Accepted a minimal raster interchange interface for `Image` and `Color`; general bitmap editing and effect functions will not remain public.
- 2026-07-22: Accepted retaining only the basic SVG text shape and current parser/renderer path; the unintegrated general text-layout toolkit will be removed.
- 2026-07-22: Reusing `Milky2018/xml` for XML syntax was proposed and split into ISS-049 because dependency integration and parser replacement are implementation work rather than a public-surface decision.
- 2026-07-22: Accepted direct breaking removal in version 0.4.0 with a migration table and no deprecated compatibility surface.
