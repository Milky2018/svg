## Description
Bring the repository into a coherent state after combining the original SVG implementation with a locally maintained copy of the mizchi/css core. The cleanup must align the public scope, workspace metadata, documentation, CI, source organization, provenance, and release process without confusing historical or generated artifacts with disposable leftovers.

## Design
Perform boundary decisions before destructive cleanup. Start by defining the supported SVG and CSS public surfaces, then remove or relocate out-of-scope code, normalize mechanical repository configuration, split oversized implementation files, and finish by aligning release metadata. Preserve attribution and historical evidence throughout.

The following are protected by default rather than presumed removable: Apache license and NOTICE files, mizchi/css provenance, closed issue history, accepted ADRs, `CONTEXT.md`, renderer baseline and cutover reports, and compiler-generated `pkg.generated.mbti` files reviewed through `moon info`. The audit found no remaining WIT, WPT generator, Justfile, `.gitmodules`, or submodule cleanup work.

## Acceptance Criteria
- [x] Every child cleanup issue is closed with its own verification evidence.
- [x] The published SVG and CSS responsibilities are explicit and match their public interfaces.
- [x] Repository documentation, manifests, CI, provenance, and release metadata describe the same workspace.
- [x] The final tree passes formatting, generated-interface review, deny-warn checks, and tests on every supported target.
- [x] Required attribution and intentional historical records remain intact.
