## Description
The renderer currently targets SVG/CSS semantic correctness, stable internal geometry, and useful visual-difference evidence. It does not promise that every subpixel input produces pixels identical to Chromium. Exact parity depends on the Chromium and Skia revisions, raster backend, platform, device pixel ratio, color management, and alpha/compositing rounding, so it must not be an implicit acceptance requirement for current renderer work.

## Design
When this work is resumed, first pin a reproducible Chromium environment and build a differential harness that renders the same corpus with Chromium and Milky2018/svg. Report exact pixel equality separately from tolerant channel error, changed-pixel ratio, and spatial edge distance. Preserve semantic tests as the primary correctness signal; do not replace them with a single integer raster score. Evaluate direct Skia reuse only as a separate cost and portability decision.

## Acceptance Criteria
- [ ] Pin and document the Chromium version, platform, raster backend, device pixel ratio, and color configuration.
- [ ] Add reproducible differential fixtures for subpixel geometry, strokes, opacity, masks, filters, blend modes, and markers.
- [ ] Report exact pixel differences, continuous channel error, and spatial edge-distance evidence separately.
- [ ] Define when `renderer_*_raster_unproven` may be cleared and when tolerant parity is sufficient.
- [ ] Document known cross-platform and cross-version nondeterminism.
- [ ] Keep SVG/CSS semantic conformance independent from Chromium pixel parity.
