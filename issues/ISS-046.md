## Description
Replace copied live-code names and comments that still describe the implementation as upstream or crater-specific even though it is now locally maintained. Examples include the `--crater-effective-color-scheme` internal key, crater issue references in implementation comments, a facade comment about crater integrations, and SVG test names beginning with `upstream`.

## Design
Use local semantic names and local issue or specification references for maintained behavior. Preserve the factual mizchi/css origin in README and NOTICE files and keep historical external references in closed issue records. Renaming an externally observable CSS custom property requires a compatibility decision or proof that it was internal-only.

## Acceptance Criteria
- [x] Live source and current test names no longer imply that the local CSS module is an external upstream dependency.
- [x] Crater-specific internal identifiers are renamed or explicitly documented as compatibility contracts.
- [x] Maintained comments point to specifications or local issues where context is still needed.
- [x] mizchi/css attribution remains intact in provenance and legal documentation.
- [x] Formatting and all-target tests pass.
