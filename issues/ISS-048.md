## Description
Make repository and published metadata reflect the post-vendoring workspace. The SVG manifest remains at 0.3.1 despite subsequent CSS vendoring and API work, the CSS module retained the copied 0.7.3 version, SVG depends on `Milky2018/css@0.7.3`, and repository tags currently stop at v0.2.1.

## Design
Define independent or coordinated version policies for `Milky2018/css` and `Milky2018/svg`, document the required CSS-before-SVG publish order, add a concise changelog, and establish tag naming for a repository with two published modules. Perform any actual publication only under a separate explicit user request.

## Acceptance Criteria
- [x] CSS and SVG versioning policies are documented and unambiguous.
- [x] Manifest versions and inter-module dependency versions match the next intended release state.
- [x] A changelog records the API and behavior changes since the last published SVG version.
- [x] Tag naming distinguishes module releases or documents a coordinated scheme.
- [x] Release validation commands and CSS-before-SVG ordering are documented.
- [x] No package is published as part of this issue without separate authorization.
